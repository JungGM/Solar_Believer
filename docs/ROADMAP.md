# 목표와 로드맵

장기 목표는 개별 발전소의 발전량·기상·전력시장 데이터를 주기적으로 수집하고,
승인된 모델로 발전소별 발전량을 예측해 VPP당 목표 20MW로 구성한 뒤
근거가 명확한 정산 시뮬레이션을 웹에서 조회하는 것이다. 시도별 발전량은 대상에서 제외한다.
첫 단계 목표는 기존 수집기를 보존하면서 2인이 동일한 환경을 실행하는 것이다.

| 단계 | 상태 | 산출물 | 완료 조건 |
|---|---|---|---|
| 1. 기반 구조 | 완료 | Compose·PostgreSQL·FastAPI·React·migration·계약·문서·CI 템플릿 | 로컬 컨테이너/조회/테스트 통과 |
| 1. PR 공동 검토 | 진행 중 | 작업 브랜치와 PR | 팀원 리뷰 후 병합 |
| CI 활성화 | 예정 | `docs/ci/service-scaffold.yml` → `.github/workflows/service-scaffold.yml` | workflow 권한 있는 개발자가 활성화 후 Checks 통과 |
| 2. 실제 수집 | 예정 | 기존 수집기 결함 보완, API→DB, 안정 ID·시간·단위·쿼터 | 실제 응답/실패/재수집 검증, 관측/예보 분리 |
| 3. 기존 모델 연결 | 예정 | 모델 출처·manifest·피처 파이프라인·추론 저장 | cutoff-safe 입력, 저장/조회 비교, 모델 호환성 검증 |
| 3. VPP 구성·집계 | 예정 | 발전소/구성원/포트폴리오 schema, 20MW 목표 배치·집계 | 동일 기준 용량·안정 ID·구성 버전·중복 배치 정책 검증 |
| 4. 정산 시뮬레이션 | 예정 | 합의된 시장 규칙·가격·버전·계산 근거 | 입력 단위·기간·예외·재계산 테스트, 시뮬레이션 표시 |
| 5. 월별 재학습 | 예정 | 스냅샷·학습·시간 순 검증·후보 등록 | 실패/성능 미달 시 기존 모델 유지, 수동 승인·적용·롤백 |
| 6. 운영 보강 | 예정 | 인증·권한·백업/복구·알림·job lease·catch-up·모니터링 | 장애 복구/복원 시험, 비밀키 관리·배포 검토 |

성능 수치나 정산 금액은 데이터와 정책이 없는 단계에서 목표 달성 결과로 적지 않는다.
정산 규칙, 데이터 이용 조건, 운영 배포 범위는 팀이 확정하고 근거를 문서화한다.
