# 목표와 로드맵

**2026-11-22 갱신:** 현재 단계와 다음 실행 순서는 [전체 진행 기록](PROGRESS.md)을 따른다.
파일 수집·예보 누적·전처리·웹 메뉴는 진행됐으며 DB 적재·실제 모델·VPP 최적화·정산 엔진은 남아 있다.
우선 pytest/Ruff 실패 및 수집 품질·자원/기상 매핑을 해결한다. 아래는 11-19 계획 원문이다.

2026-11-19 기준 우선 작업은 [팀원 작업 인계](TEAM_HANDOFF.md)의 작업 ID와 완료 기준을 따른다.
장기 목표는 지속 수집 가능한 개별 태양광 발전기 200개 이상의 발전량·기상·전력시장 데이터를 확보하고,
승인된 모델로 발전기별 발전량을 예측해 최소 2개 VPP(예측제도 기준 주요자원 용량 각각 20MW 초과)를 구성한 뒤
근거가 명확한 정산 시뮬레이션을 웹에서 조회하는 것이다. 시도별 발전량은 대상에서 제외한다.
첫 단계 목표는 기존 수집기를 보존하면서 2인이 동일한 환경을 실행하는 것이다.

| 단계 | 상태 | 산출물 | 완료 조건 |
|---|---|---|---|
| 1. 기반 구조 | 완료 | Compose·PostgreSQL·FastAPI·React·migration·계약·문서·CI 템플릿 | 로컬 컨테이너/조회/테스트 통과 |
| 1. PR 공동 검토 | 진행 중 | 작업 브랜치와 PR | 팀원 리뷰 후 병합 |
| CI 활성화 | 예정 | `docs/ci/service-scaffold.yml` → `.github/workflows/service-scaffold.yml` | workflow 권한 있는 개발자가 활성화 후 Checks 통과 |
| 2. 실제 수집 | 진행 중 | 원천 CSV·남동/SMP/기상 호출 코드 추가. 인자/반환형 수정·API→DB·안정 ID·쿼터는 후속 | 실제 응답/실패/재수집 검증, 관측/예보 분리 |
| 2. 지속 수집 자원 확대 | 예정 | 남동·남부·중부·서부의 실제 자원·최신 갱신 조사표 | 중복 제거 후 지속 수집 가능한 200개 이상. 미달 시 부족 수와 추가 제공 경로 기록 |
| 2. CSV 적재·품질·과거 예보 | 예정 | 원본 보존 적재·결측/이상치/시각 보고·발표 이력 | DB 행 수/재실행 검증, cutoff 이전 입수 정보만 모델 입력 |
| 3. 기존 모델 연결 | 예정 | 모델 출처·manifest·피처 파이프라인·추론 저장 | cutoff-safe 입력, 저장/조회 비교, 모델 호환성 검증 |
| 3. VPP 구성·집계 | 진행 중 | schema·기간별 조회·지도/필터·남동 임시 구성 코드. 실제 자원 검증·배치는 후속 | 최소 2개 그룹, 각각 주요자원 20MW 초과·적격성·안정 ID·유효기간·중복 정책 검증 |
| 4. 정산 시뮬레이션 | 예정 | SETTLEMENT_RULES.md에 근거/단가/예외 조사. 엔진 미구현 | 판매금액 추정·예측 인센티브 구분, 단위·기간·예외·재계산 테스트 |
| 5. 월별 재학습 | 예정 | 스냅샷·학습·시간 순 검증·후보 등록 | 실패/성능 미달 시 기존 모델 유지, 수동 승인·적용·롤백 |
| 6. 운영 보강 | 예정 | 인증·권한·백업/복구·알림·job lease·catch-up·모니터링 | 장애 복구/복원 시험, 비밀키 관리·배포 검토 |

성능 수치나 정산 금액은 데이터와 정책이 없는 단계에서 목표 달성 결과로 적지 않는다.
정산 규칙, 데이터 이용 조건, 운영 배포 범위는 팀이 확정하고 근거를 문서화한다.
