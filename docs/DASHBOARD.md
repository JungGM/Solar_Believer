> **2026-11-27 현재 방향:** [개별 발전기 평가 계약](INDIVIDUAL_SETTLEMENT_DIRECTION.md)이 우선한다.
> 데스크톱 후속 개편에서는 발전기·기간·모델을 선택하고, 동일 실측·SMP 조건의 최대·최소 가능 금액과
> 사후 모의정산금·미획득 인센티브·획득률·평가 시간 수를 비교한다. VPP 구성과 그룹 성과는 이번 범위에서 제외한다.

## 운영 메뉴 (2026-11-22)

사이드바를 아래 7개 메뉴로 재구성했다. `?page=forecast&demo=true`처럼 메뉴와 데모 선택은
URL에 남아 새로고침과 브라우저 앞/뒤 이동 시 유지된다. 실제 기본값은 `page=home&demo=false`다.

| 메뉴 | 화면 |
|---|---|
| 홈 · 운영 현황 | 내일 전체 예측, 오늘 실측·오차·저장 정산, 내일/오늘 그래프, 지도, 운영 확인 항목 |
| 내일 발전량 예측 | 기본 대상일 내일, 시간별 예측·피크·생성 시각·발전기별 예측 |
| 발전 실적 · 정산 | 일/월/연 비교, VPP 오차·SMP, 규칙별 저장 정산과 잠정 표시 |
| 발전기 지도 · 이력 | 미소속 자원 포함 실제 등록 발전기, 검색·상태 필터, 최초/최종 관측, VPP 소속 기간 |
| 날씨 · 예보 비교 | 날짜·지점·자료 종류 필터, 저장된 예보 발표분과 관측, 지점 연결 미검증 표시 |
| VPP 구성 · 분석 | 구성 버전·목표 용량, 구성원, 동일 시간 개별 오차 합 대비 VPP 오차 감소율, 소속 기간 |
| 데이터 · 모델 관리 | 작업·수집·예측·정산·모델 버전·학습 이력을 탭으로 조회 |

새 운영 화면은 `prediction_policy=day_ahead`로 조회한다. 임시 서비스 비교 기준은
**대상일 전일 18:00 KST**이며 공식 제출 시각을 의미하지 않는다. `cutoff_at`과
`created_at`이 모두 이 기준 이하이고 현재 이전인 예측만 사용한다. 늦게 삽입한 과거 예측과
당일 재예측은 제외한다. 실제 제출 마감·차수가 정해지면 별도 정책으로 확장한다.
기존 API 기본값 `prediction_policy=latest`는 호환을 위해 유지한다.

홈의 내일 총량은 모든 참여 시간에 전체 구성원의 예측이 확보되었을 때만 표시한다.
예측 화면의 부분 합계는 확보 시간과 함께 표시한다. VPP 비교는 모든 구성원의 실측·예측이
있는 같은 시간만 사용하며, 개별 오차 합과 VPP별 합산 절대오차의 시간 평균을 비교한다.
개별 오차가 모두 0이면 감소율은 미표시다. 이것은 그룹 최적화나 정산 수익 개선 검증이 아니다.

`GET /api/v1/workspace/plants`는 실제 발전기 전부와 정규 원천 실측의 최소/최대 대상 시각,
최근 수집 시각, VPP 소속 기간을 읽는다. 최종 대상 시각이 현재보다 7일 이상 오래되면
장기 미수집으로 표시한다. 실측 0은 관측으로 인정하며, 최초 관측을 준공일이나 최종 관측을
폐지일로 해석하지 않는다. 설비·좌표·용량 변경 이벤트 기록과 실제 폐지 확인은 후속 연동이다.

`GET /api/v1/workspace/weather?date=YYYY-MM-DD&scope_id=...`는 실제 저장 기상 기록만
최대 500건 조회한다. 제한에 걸리면 지점 필터 사용 안내를 표시한다. 발전소·예보 격자·관측소의
대응 관계가 미검증이므로 서로 다른 지점이나 운량/하늘상태 코드의 오차를 임의 계산하지 않는다.
발전기 이력·기상·관리 화면에서는 데모 자원을 실제 이력으로 표시하지 않는다.

정산 엔진은 이번 UI 변경에 포함하지 않았다. SMP 판매금액 추정과 예측 인센티브는
계산 연동 대기로 구분한다. 기존 저장 정산은 규칙별로 읽되 하루 전 예측 차수와의 연결이
미검증임을 표시한다. 당일·불완전 실측은 잠정이며, 실측 확보 완료도 실제 지급 확정이 아니다.

구현 위치: `frontend/src/Workspace.jsx`, `components/WorkspaceShared.jsx`,
`components/AssetWeather.jsx`, `workspace.css`, `backend/app/workspace.py`.
기존 `Dashboard.jsx`는 보존하고 새 메뉴 진입점은 `main.jsx`에서 제공한다.

## 기존 조회·집계 계약

기본 화면은 실제 DB 조회다. 한국 지도, 그룹·모델·기간 선택, 발전량 비교, SMP,
발전량 오차, 저장된 정산/손실, 발전소 목록과 데이터 확보율을 제공한다.
키·모델·발전소가 없으면 빈 상태를 표시하며 `데모 데이터 보기`를 직접 선택할 수 있다.
데모는 가상 발전소 8개·20MW 목표 그룹 2개·가상 모델 2개를 메모리에서 만들고
DB에 저장하지 않는다. 정산금이나 금전적 손실은 데모에서도 만들지 않는다.
이 20MW 데모는 화면 확인용이며 예측제도 적격성 사례가 아니다. 실제 목표는 지속 수집 자원
200개 이상·최소 2개 VPP이며 예측제도 기준 주요자원 용량은 그룹별 20MW 초과다.
[팀원 인계](TEAM_HANDOFF.md)와 [정산 표시·계산 기준](SETTLEMENT_RULES.md)을 함께 읽는다.

## 조회와 집계 기준

| 선택 | 표시 |
|---|---|
| VPP 그룹 | 전체 또는 선택 그룹의 적용 기간에 속한 발전소·지도 지점·그래프·요약 |
| 모델 | 해당 model_version_id의 저장된 예측. 모델을 바꿔도 실측과 SMP는 유지 |
| 일별 | KST 하루의 24개 시간 구간 |
| 월별 | 선택 월의 일별 합계. 28/29/30/31일 반영 |
| 연별 | 선택 연도의 월별 합계. 윤년 반영 |
| 정산 규칙 | 선택한 버전의 저장된 VPP 정산금·금전적 손실. 여러 규칙을 합산하지 않음 |

발전량은 kWh로 저장하고 웹에서 MWh로 변환한다. 설치 용량은 kW→MW다.
SMP는 원/kWh이며 육지·제주를 별도 선으로 표시한다. 월·연 조회의 SMP는 확보된
시간별 가격의 단순 평균이며 전력량 가중 평균이나 미래 가격 예측이 아니다.

예측은 모델·발전소·대상 시각마다 cutoff_at이 대상 시각 이하인 가장 최근 예측을 선택한다.
대상 이후 생성된 예측은 제외한다. 고정된 하루 전 예측 성능을 보장하는 정책은 아니므로,
운영 예측 마감 시각이 확정되면 해당 cutoff 정책을 추가해야 한다.

실측은 plants.generation_source와 일치하는 정규화 원천만 읽고, 같은 대상 시각의
개정 자료는 현재 입수 가능한 가장 최근 available_at을 선택한다.
관측·예측 시간은 UTC 정규화한 시간 구간 시작점으로 연결한다. API의 거래시간 끝점은
수집 adapter에서 변환해야 한다. SMP는 source=`kpx_smp`, scope_id=`market:land`/`market:jeju`,
values의 `smp_krw_kwh`를 사용한다.

누락 발전량을 0으로 채우지 않는다. VPP의 모든 참여 발전소 값이 있는 시간만
완전한 VPP 합계로 사용한다. 일·월 그래프 합계는 구성 시간들이 모두 완전할 때 표시한다.
요약 총량과 발전소 표는 확보된 시간들의 합계이며 확보 시간 수를 함께 표시한다.
예측·실측의 확보 구간이 다르면 두 총량을 직접 비교하면 안 된다.

오차는 **VPP 안에서 합산한 예측과 실측의 차이에 절대값**을 적용한다.
전체 VPP 조회 시에는 각 VPP의 절대오차를 더해 서로 다른 VPP 오차의 상쇄를 막는다.
요약의 MAE는 이 시간별 오차 값의 평균이다. 원 단위 손실과 구별한다.
오차 비교는 예측과 실측이 모두 완전한 시간만 포함한다.

## 발전소·구성원·정산 저장

`0002_vpp_dashboard` migration이 기존 데이터·테이블을 유지하며 아래를 추가한다.

- `plants`: 안정 ID, 이름, 설비용량, 위경도, 가격 구역, 정규화 발전량 원천.
  id는 기존 observations/predictions의 scope_id와 같아야 한다. 이 두 필드는 기존 데이터
  호환을 위해 문자열이며 FK로 강제하지 않는다.
- `vpp_portfolios`: 그룹 ID·이름·slug·구성 버전·목표 용량.
- `vpp_memberships`: 그룹·발전소 FK, 적용 시작과 종료(종료는 미포함).
- `vpp_settlements`: 그룹·모델 FK, 대상 시각·규칙 버전·정산금·선택적 손실·계산 근거·시뮬레이션 여부.

실제 자원의 용량·적격성을 검증해 배치하는 구성 알고리즘과 등록/수정 API는 아직 구현하지 않았다.
읽기 화면이 등록된 구성원을 집계한다. 동시 중복 배치가 있으면 경고하고 해당 시간의
오차·금액 표시를 제외한다. 용량 요약은 선택 기간에 참여한 고유 발전소의 등록 용량 합계다.
기간 중 구성 변경 시 순간 VPP 용량과 다를 수 있으며 과거 용량 변경 이력은 후속 확장이다.

지도 좌표가 없는 발전소는 지도에서만 제외하고 표·집계에는 포함한다.
VPP 합산 예측은 조회 시 계산하며 별도 vpp_predictions 테이블에 저장하지 않는다.
기존 settlements는 예측 행에 연결된 기존 기록이고, VPP 정산 그래프는 vpp_settlements만
사용한다. 개별 발전소 정산금을 임의로 합쳐 VPP 정산금으로 사용하지 않는다.
정산 엔진이 연결되면 details에 사용한 입력/구성·가격·계산 근거를 기록해야 한다.

## API

- `GET /api/v1/dashboard/options?demo=false`: VPP·모델·규칙 선택 목록.
- `GET /api/v1/dashboard?period=day&date=2026-11-17`: 요약·시간축·발전소·경고.
- 선택 파라미터: `portfolio_id`, `model_version_id`, `settlement_rule_version`, `demo`.
- 기간: day/month/year, date는 YYYY-MM-DD, 지원 연도 2000~2100.
- 잘못된 그룹·모델·규칙·기간은 422. 모든 경로는 읽기 전용이다.

새 운영 화면의 메뉴·데모 선택은 URL query로 남고, 기간·모델·VPP 선택은 화면 내 상태로 유지된다.
기존 `Dashboard.jsx`의 전체 필터 query 동기화 구현은 보존했다. 요청 변경 시 이전 요청을 취소하고
이전 결과를 비워 다른 조건의 값이 현재 결과처럼 보이지 않도록 한다. API가 15초 안에 응답하지
않으면 지연 메시지와 새로고침 안내를 표시한다.

지도 경계·투영 출처는 [MAP_SOURCE.md](MAP_SOURCE.md)에 기록했다.
지도를 위해 별도 API 키나 런타임 외부 타일 요청이 필요하지 않다.
