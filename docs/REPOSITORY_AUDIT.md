## 조사 범위와 발견 사항

기준 커밋은 추적 파일 13개, 폴더 `API/` 하나로 구성된다. 모델 바이너리,
학습 스크립트, 노트북, 모델 검증 결과, 웹서비스, DB, Docker 구성은 없다.
`data/`와 CSV는 Git 제외 대상이다. 기존 README의 데이터 수량·수집 완료 주장은
설명으로만 보존했으며 실제 데이터 보유나 정확성을 이번 작업에서 검증하지 않았다.
다른 저장소의 모델이나 비공개 경쟁 데이터는 가져오지 않았다.

## 후속 연동 전 검토할 기존 코드

- `API/config.py`에 인증키로 보이는 리터럴 기본값이 있었다. 이번 변경에서 제거했다.
  과거 Git 이력은 바꾸지 않았으므로 키 소유자가 발급처에서 해당 키를 폐기·재발급해야 한다.
  인증키 값은 문서·테스트·PR에 복사하지 않는다.
- `KVPPOrchestrator._save`는 같은 파일명 CSV를 덮어쓸 수 있다.
  새 작업은 이를 자동 실행하지 않는다. 원본 CSV 보존 정책을 확정한 뒤 연결한다.
- SMP 클래스에는 API 수집 메서드가 있지만 기존 오케스트레이터는 로컬 CSV만 사용한다.
  새 구조가 실제 SMP API 수집까지 완료했다고 해석하면 안 된다.
- `KPXSMPCollector.load_from_csv`의 일반 세로형 분기는 정의되지 않은
  `_standardize_dataframe`을 참조한다. 가로형 EPSIS 경로와 구별하여 수정·검증이 필요하다.
- 발전량 변환에는 결측 0 대체와 음수 절삭, 거래시간 1~24→0~23 변환이 있다.
  단위 추정, 시간 구간 시작/끝, 결측 발전량을 검토한 뒤 학습 데이터에 반영해야 한다.
- `mark_interpolated`는 지역별 그룹 없이 선형 보간한다. 지역 간 보간 및
  미래 관측치 사용 가능성을 배제하는 수정이 후속 단계에 필요하다.
- 예보는 `base_date`, `base_time`을 반환하지만 실제 입수 시각은 저장하지 않는다.
  신규 DB에서는 발표·대상·입수 가능 시각을 구별해야 한다.
- `KPX_PV_{region}`는 지역 집계 식별자다. 발전소 허가 CSV의 개별 발전소 ID와
  같은 대상으로 결합해서는 안 된다. 허가 CSV ID도 행 인덱스에 따라 달라진다.
- 일부 기존 수집기는 오류를 빈 DataFrame으로 바꾸거나 URL이 포함된 예외를 기록한다.
  실서비스 연결 전 부분 수집/실패 구분과 인증키 로그 마스킹을 검증해야 한다.

## 구조 결정

기존 코드를 이동하면 상대 import·CLI·로컬 파일 자동 탐색을 깨뜨릴 수 있다.
따라서 `API/`와 `api.py`를 유지하고 기능별 신규 폴더를 추가한다.
`backend/app/adapters/legacy.py`를 접점으로 두고, 파일 저장 오케스트레이터 대신
각 수집 클래스의 반환값을 검증해 DB에 저장하도록 후속 구현한다.
모델이 저장소에 없으므로 임의의 모델을 기존 모델로 등록하지 않는다.
