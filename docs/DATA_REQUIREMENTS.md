# 발전량 예측 → VPP 구성 → SMP·정산 시뮬레이션의 데이터 요구

확인일: 2026-11-19 (KST). 사용자 확정 방향은 **지속 수집 가능한 개별 태양광 발전기
200개 이상을 확보해 예측한 뒤, 최소 2개 VPP**를 구성하고 SMP와 정산식을
적용해 웹에 표시하는 것이다. 시도별 발전량 예측/집계는 이 서비스의 목표에서 제외한다.
예측제도 기준 각 그룹 주요자원 용량은 **20MW 초과**다. 정확히 20MW로 맞추거나
20MW를 상한으로 삼지 않는다. 참여 자원 적격성·구성·등록시험 조건은 별도로 검증한다.
발전기 수 200개는 프로젝트 목표다. [팀원 인계](TEAM_HANDOFF.md)와 [정산 명세](SETTLEMENT_RULES.md)를 함께 따른다.
계산식은 백엔드에서 버전·입력·결과를 저장하고 웹은 조회한다.

SMP의 시간별 행이 있다는 사실을 매시간 새 가격이 발표된다는 뜻으로 해석하지 않는다.

## API 종류가 충분한지 판단하는 기준

**현재 필요한 API/데이터가 모두 확보된 상태는 아니다.**
23개 과거 발전기 자료는 들어왔지만 200개 이상의 지속 수집·메타데이터 검증·DB 적재·과거 예보는 부족하다.
KPX API는 회원 태양광의 시도별 집계이며 허가 CSV는 위치·용량 정보다.
발전소 허가 목록에 있는 개별 발전소의 발전량 이력이 제공되는 것으로 볼 수 없다.
집계 발전량을 용량 비율로 임의 분할해 개별 실측·독립 오차로 사용하지 않는다.
설비용량 분모가 필요한 식이면 발전량과 동일 대상·동일 기간의 용량도 확보해야 한다.
남동발전 원천은 해당 회사 설비를 대상으로 하며 전국 모든 발전소 이력을 제공한다고
가정하지 않는다. 실제 자원 수와 용량이 주요자원 20MW 초과 VPP를 최소 2개 구성하기에 충분한지 검증해야 한다.
일별 발전량만 제공하는 다른 원천은 시간별 발전량을 대체하지 못한다.
CSV의 `총량(KW)` 같은 모호한 명칭을 설비용량으로 바로 사용하지 않는다.
발전소별 위경도→예보 격자, 적합한 관측소, 육지/제주 가격 구역을 매핑하고
동일 격자는 한 번 수집해 여러 발전소가 참조하도록 한다. 기존 시도 대표 격자는 그대로 사용하지 않는다.

학습과 운영 피처를 맞추려면 **발표시각이 남아 있는 과거 예보**도 필요하다.
기존 코드의 과거 날짜 입력만으로 해당 기간 전체의 예보 다운로드가 보장되는 것은 아니다.
과거 예보 자료의 접근 범위·배포 방식·승인을 따로 확인하고, 지금부터는 모든 발표분을 누적한다.
단기예보의 현재 반환 항목에는 직접적인 일사량 예측값이 없다. 일사 예보를 피처로 선택하는
모델은 해당 원천을 추가하거나, 실제 입수 가능한 피처만으로 모델을 구성해야 한다.

예상 수익 표시는 예측 발전량과 그 시점에 알려진 가격/가격 가정으로 계산할 수 있다.
예측오차를 쓰는 정산식의 사후 검증에는 실제 발전량이 추가로 필요하다.
미래 SMP가 공개되기 전에는 미래 확정가격을 알고 계산한 것처럼 표시하지 않는다.
발전량 모델의 예측 기준과 가격 시나리오/사후 정산 시점을 각각 보존한다.

VPP 구성 계산은 구성원별 예측과 필요 시 실제값을 같은 포트폴리오·시간 구간으로 집계한 뒤,
선택한 규칙에 적용한다. 다른 지역의 발전량을 겹쳐 담거나 육지/제주 가격을 섞지 않는다.
용량·출력제어·가격·오차 중 어떤 입력이 필요한지는 정산식 확정 후 결정한다.
REC 등 다른 수익 항목은 사용자가 수익 범위에 포함할 때만 추가 검토한다.

## 키 담당과 현재 수집 상태

키 발급·활용 신청은 다른 팀원이 맡는다. 로컬 `.env` 확인 결과 `DATA_GO_KR_API_KEY`와
`KMA_APIHUB_KEY`는 미설정이다(2026-11-19 이 PC의 파일/호스트 프로세스 기준). 팀원 PC의 키 보유 여부는 미확인이다. 기존 하드코딩 키는 재사용하지 않는다.
공공데이터포털 키는 선택한 서비스별 활용 승인도 확인해야 한다.
실제 API 수집 실행·응답 검증은 키 준비 후 진행하며, 현재는 인터페이스·DB 저장·
가짜 응답/시간 경계 테스트와 문서 작업을 진행한다. 승인된 키는 각 개발 환경에 별도로 설정하고 Git에 올리지 않는다.
