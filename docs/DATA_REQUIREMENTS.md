# 발전량 예측 → VPP 구성 → SMP·정산 시뮬레이션의 데이터 요구

확인일: 2026-11-17 (KST). 사용자 확정 방향은 **개별 발전소별 발전량을 예측한 뒤,
VPP당 목표 용량 20MW(20,000kW)로 여러 포트폴리오를 구성**하고 SMP와 정산식을
적용해 웹에 표시하는 것이다. 시도별 발전량 예측/집계는 이 서비스의 목표에서 제외한다.
20MW는 현재 설계 목표로 기록하며, 실제 시장 참여 적격성을 검증한 수치로 표시하지 않는다.
정확한 상한·허용 용량 차이·발전소 분할 허용 여부는 구성 정책에서 명시할 후속 항목이다.
계산식은 백엔드에서 버전·입력·결과를 저장하고 웹은 조회한다.

## 현재 원천과 수집 코드

원천을 찾은 상태, 수집 코드가 있는 상태, 실제 API→DB 연동 완료를 구별한다.
현재 실제 원천의 DB 연동은 모두 예정이며 API 키를 사용한 응답 검증은 하지 않았다.

| 데이터 | 원천·현재 코드 | 원천의 시간 특성 | 수집 운영안 / 부족한 부분 |
|---|---|---|---|
| 기상 단기예보 | KMA getVilageFcst, `KMAForecastCollector` | 02·05·08·11·14·17·20·23시 발표 | 발표 20분 뒤 별도 forecast 작업 예약 완료; 발전소별 격자 매핑·실제 호출·DB 매핑·미제공 재시도는 예정 |
| 과거/현재 기상 관측 | ASOS, `KMAObsCollector` | 시간 자료 조회 | 매시 관측값 입수 확인, 누락 구간 재조회 제안; 미래 예측 피처로 미래 관측을 사용하지 않음 |
| 개별 발전소 실제 발전량 | 새 발전소별 원천 필요; 남동발전 시간대별 태양광 API를 후보로 확인 | 포털 갱신주기 실시간 표기; 실제 지연은 미검증 | 대상 발전소 수·기간·시간별 값·안정 ID·총 설비용량을 키 발급 후 검증; 현 코드 미연동 |
| 발전소별 과거 발전량·메타데이터 | 남동발전 시간대별 태양광 실적 및 메타데이터 CSV 후보 | 설명상 2022~2026.08 이력, 연간 갱신 | 위치·실제 설비용량·ID 대응 검토 후 학습용으로 선정; 파일 미취득 |
| 기존 KPX 시도별 발전량 API/CSV | `KPXSolarCollector` | 시도별 집계 | 원본 코드 보존용. 개별 발전소/VPP 모델의 실측 데이터로 사용하지 않음 |
| SMP·수요예측 | KPX SmpWithForecastDemand, `KPXSMPCollector` | 육지/제주 시간별 값; 상세설명상 하루 1회 23시경 갱신 | 23:20 확인 후 미제공 재조회 제안; 아직 별도 예약 미적용. 기존 오케스트레이터는 CSV만 사용 |
| 발전소 위치·설비용량·상태 | 전국 발전소 허가 표준 CSV, `SolarPlantCollector` | 정적/비정기 갱신 원천 | 초기 적재 후 월별 변경 확인 제안. 현재는 CSV 로더이며 자동 API 수집기 아님 |
| VPP 구성원·배분·적용 기간 | 우리 서비스가 정의하는 설정/DB | 사용자 구성 변경 시 버전 생성 | 저장 테이블·기간별 조회 집계 완료; 실제 자산 등록·자동 배치는 미구현 |
| 정산 규칙 | 선택한 시뮬레이션의 근거 문서·식 | 적용 버전·기간별 | 외부 API 대신 버전 있는 계산 모듈로 구현; 현재 규칙 미설정 |

20분은 운영자가 선택한 수집 지연 버퍼다. API가 그 시각에 반드시 응답한다는 보장은 아니다.
발전량·SMP의 데이터 날짜, 거래시간의 구간 끝점, 실제 입수 시각을 별도로 검증한다.
SMP의 시간별 행이 있다는 사실을 매시간 새 가격이 발표된다는 뜻으로 해석하지 않는다.

## API 종류가 충분한지 판단하는 기준

**현재 필요한 API/데이터가 모두 확보된 상태는 아니다.**
사용자 목표에 필요한 발전소별 시간별 실제 발전량 이력과 안정적인 발전소 메타데이터가 부족하다.
KPX API는 회원 태양광의 시도별 집계이며 허가 CSV는 위치·용량 정보다.
발전소 허가 목록에 있는 개별 발전소의 발전량 이력이 제공되는 것으로 볼 수 없다.
집계 발전량을 용량 비율로 임의 분할해 개별 실측·독립 오차로 사용하지 않는다.
설비용량 분모가 필요한 식이면 발전량과 동일 대상·동일 기간의 용량도 확보해야 한다.
남동발전 후보 원천은 해당 회사 설비를 대상으로 하며 전국 모든 발전소 이력을 제공한다고
가정하지 않는다. 실제 표본 수와 용량이 여러 20MW VPP를 구성하기에 충분한지 검증해야 한다.
일별 발전량만 제공하는 다른 원천은 시간별 발전량을 대체하지 못한다.
CSV의 `총량(KW)` 같은 모호한 명칭을 설비용량으로 바로 사용하지 않는다.
발전소별 위경도→예보 격자, 적합한 관측소, 육지/제주 가격 구역을 매핑하고
동일 격자는 한 번 수집해 여러 발전소가 참조하도록 한다. 기존 시도 대표 격자는 그대로 사용하지 않는다.

학습과 운영 피처를 맞추려면 **발표시각이 남아 있는 과거 예보**도 필요하다.
기존 코드의 과거 날짜 입력만으로 해당 기간 전체의 예보 다운로드가 보장되는 것은 아니다.
과거 예보 자료의 접근 범위·배포 방식·승인을 따로 확인하고, 지금부터는 모든 발표분을 누적한다.
단기예보의 현재 반환 항목에는 직접적인 일사량 예측값이 없다. 일사 예보를 피처로 선택하는
모델은 해당 원천을 추가하거나, 실제 입수 가능한 피처만으로 모델을 구성해야 한다.

예상 수익 표시는 예측 발전량과 그 시점에 알려진 가격/가격 가정으로 계산할 수 있다.
예측오차를 쓰는 정산식의 사후 검증에는 실제 발전량이 추가로 필요하다.
미래 SMP가 공개되기 전에는 미래 확정가격을 알고 계산한 것처럼 표시하지 않는다.
발전량 모델의 예측 기준과 가격 시나리오/사후 정산 시점을 각각 보존한다.

VPP 구성 계산은 구성원별 예측과 필요 시 실제값을 같은 포트폴리오·시간 구간으로 집계한 뒤,
선택한 규칙에 적용한다. 다른 지역의 발전량을 겹쳐 담거나 육지/제주 가격을 섞지 않는다.
용량·출력제어·가격·오차 중 어떤 입력이 필요한지는 정산식 확정 후 결정한다.
REC 등 다른 수익 항목은 사용자가 수익 범위에 포함할 때만 추가 검토한다.

## 키 담당과 현재 수집 상태

키 발급·활용 신청은 다른 팀원이 맡는다. 로컬 `.env` 확인 결과 `DATA_GO_KR_API_KEY`와
`KMA_APIHUB_KEY`는 미설정이다. 기존 하드코딩 키는 재사용하지 않는다.
공공데이터포털 키는 선택한 서비스별 활용 승인도 확인해야 한다.
실제 API 수집 실행·응답 검증은 키 준비 후 진행하며, 현재는 인터페이스·DB 저장·
가짜 응답/시간 경계 테스트와 문서 작업을 진행한다. 승인된 키는 각 개발 환경에 별도로 설정하고 Git에 올리지 않는다.
